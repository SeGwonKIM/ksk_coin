# F3 — 채굴 인프라: 건물이 채굴장이다

**먼저 `ksk-contract` 스킬을 읽는다.** 작업 구역은 `grep -n "\[F3:" index.html` 세 곳뿐이다.

## 선행 조건

**F2(부동산)가 완료돼 있어야 한다.** 이 층은 `ESTATES` 의 `kw`·`cool`·`fee` 필드와
`S.re.owned` 를 읽는다. F2 없이 시작하면 붙일 데이터가 없다.

```bash
grep -n "ESTATES\|S.re.owned" index.html    # 있어야 한다
```

없으면 작업을 멈추고 F2 가 먼저 필요하다고 보고한다. 데이터를 임의로 만들지 않는다.

## 이 층이 하는 일

"어디서 캐는가"가 "얼마를 버는가"를 결정하게 만든다.

- 원룸은 수용 전력이 작아 폰 몇 대가 한계다.
- 큰 건물은 수용 전력이 크고 냉각이 잘 되어 **같은 폰으로 전기를 덜 쓴다.**
- 대신 매입가와 관리비가 든다.

## 상태

```js
mine: { at: null, place: {} },   // F3 — at: 채굴 중인 건물id, place: {폰id: 대수}
```

## 만들 기능

| | 내용 |
|---|---|
| F3.2 | 수용 전력 한도 — 배치한 폰의 총 W 가 건물 `kw` 를 넘으면 배치 거부 |
| F3.3 | 냉각 효율 — 건물 `cool` 계수를 전기요금에 곱한다 |
| F3.4 | 배치 UI — 보유 건물 중 하나를 채굴장으로 고르고, 폰을 몇 대 넣을지 정한다 |
| F3.6 | 소음·민원 — 주거용 건물에서 한도의 80% 를 넘으면 확률적으로 민원, 벌금·강제 정지 |

## 공유 접점 — 전기요금 배수

`costPerSec()` 은 F0 소유다. 직접 고치지 않고 **차액만 훅에서 조정한다.**

```js
/* ==== [F3:채굴인프라] JS 시작 ==== */
function coolFactor(){
  if(!S.mine.at) return 1;                     // 배치 안 했으면 기준값
  const e = ESTATES.find(x => x.id === S.mine.at);
  return e ? e.cool : 1;
}
tickHooks.push(function(dt){
  if(!M.on) return;
  const base = elecRate() * totalKw();         // F0 가 이미 청구한 기준 전기요금
  S.cash -= base * (coolFactor() - 1) * dt;    // 차액만. cool<1 이면 환급된다
});
/* ==== [F3:채굴인프라] JS 끝 ==== */
```

**부호를 조심한다.** `cool` 이 1보다 작으면 이 식은 현금을 **더해 준다**(할인). 의도한 동작이다.
`coolFactor()` 를 전역으로 노출해 화면에서도 표시한다.

## 규칙

- 수용 전력을 넘기는 배치는 **버튼을 비활성**하고 이유를 보여준다. 조용히 실패하지 않는다.
- 관리비(`fee`)는 F5 가 월 정산으로 걷는다. F3 는 걷지 않는다 — 이중 청구가 된다.
- 배치한 건물을 F2 에서 매도하면 `S.mine.at` 을 `null` 로 되돌려야 한다.
  F2 의 매도 함수를 고치는 대신, 훅에서 **보유 목록에 없으면 해제**하는 방어 코드를 둔다.
- 폰 대수는 `S.counts` (F0 소유)를 넘을 수 없다. 배치 합계를 검사한다.

## 끝내기 전

1. `ksk-verify` 절차 통과
2. 건물을 채굴장으로 지정 → 초당 전기요금이 실제로 달라지는 것이 화면에서 확인됨
3. 한도 초과 배치가 막히는지, 건물을 팔면 배치가 해제되는지 확인
4. 초당 비용이 음수가 되거나 현금이 폭증하지 않는지 (부호 오류 검사)
5. `PRD.md` §6 의 F3 항목 갱신
6. 커밋: `feat: F3 건물을 채굴장으로 — 수용 전력·냉각 효율 반영 …`
