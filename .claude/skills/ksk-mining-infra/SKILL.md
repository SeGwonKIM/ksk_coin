# F3 — 채굴 인프라: 건물이 채굴장이다

**먼저 `ksk-contract` 스킬을 읽는다.** 작업 구역은 `grep -n "\[F3:" index.html` 세 곳뿐이다.

## 선행 조건

**F2(부동산)가 완료돼 있어야 한다.** 이 층은 `ESTATES` 의 `kw`·`cool`·`fee` 필드와
`S.re.owned` 를 읽는다. F2 없이 시작하면 붙일 데이터가 없다.

```bash
grep -n "ESTATES\|S.re.owned" index.html    # 있어야 한다
```

없으면 작업을 멈추고 F2 가 먼저 필요하다고 보고한다. 데이터를 임의로 만들지 않는다.

## 이 층이 하는 일

"어디서 캐는가"가 "얼마를 버는가"를 결정하게 만든다.

- 원룸은 수용 전력이 작아 폰 몇 대가 한계다.
- 큰 건물은 회선을 많이 깔 수 있고, **운영비(전기 + 통신)가 싸다.**

### `cool` 의 의미가 바뀌었다 (구현 중 정정)

이 스킬을 쓸 때는 채굴 장비가 GPU·ASIC 팜(2~28kW)이라 전기요금이 비용의 대부분이었다.
그 뒤 **폰 채굴로 바뀌면서** 폰은 4~18W 가 되어 전기가 총비용의 6~14% 로 떨어졌다.
냉각 계수를 전기요금에만 곱하면 데이터센터(0.55)에서도 **총비용이 6% 밖에 줄지 않아**
건물을 살 이유가 사라진다.

→ `cool` 을 **운영 효율 계수**로 넓혀 **전기 + 통신비 모두**에 곱한다.
근거도 현실적이다 — 제대로 된 건물은 냉각만 좋은 게 아니라 **기업 회선 요율**을 받는다.

`kw` 도 폰에게는 조여지지 않는 한도다(원룸 300W = 태블릿 16대).
그래서 **회선 수 한도** `max(1, round(kw × 6))` 로 환산한다. 토지(kw 0)는 채굴장이 못 된다.
- 대신 매입가와 관리비가 든다.

## 상태

```js
mine: { at: null, place: {} },   // F3 — at: 채굴 중인 건물id, place: {폰id: 대수}
```

## 만들 기능

| | 내용 |
|---|---|
| F3.2 | 회선 수 한도 (`kw × 6`) — 넘으면 배치 버튼 비활성 |
| F3.3 | 운영 효율 — 건물 `cool` 계수를 **전기 + 통신비**에 곱한다 |
| F3.4 | 배치 UI — 보유 건물 중 하나를 채굴장으로 고르고, 폰을 몇 대 넣을지 정한다 |
| F3.6 | 소음·민원 — 주거용 건물에서 한도의 80% 를 넘으면 확률적으로 민원, 벌금·강제 정지 |

## 공유 접점 — 전기요금 배수

`costPerSec()` 은 F0 소유다. 직접 고치지 않고 **차액만 훅에서 조정한다.**

```js
/* ==== [F3:채굴인프라] JS 시작 ==== */
function coolFactor(){
  const e = minedAt();
  if(!e || S.mine.penalty > 0) return 1;       // 미배치·민원 중이면 할인 없음
  const n = phoneCount();
  if(n <= 0) return 1;
  // 건물에 실제로 배치한 폰의 비율만 할인을 받는다
  return 1 - (1 - e.cool) * (Math.min(placedCount(), n) / n);
}
tickHooks.push(function(dt){
  if(!M.on) return;
  // F0 가 이미 기준 운영비(전기+통신)를 청구했다. 차액만 조정한다.
  S.cash -= costPerSec() * (coolFactor() - 1) * dt;   // cool<1 이면 더해진다(할인)
});
/* ==== [F3:채굴인프라] JS 끝 ==== */
```

**부호를 조심한다.** `cool` 이 1보다 작으면 이 식은 현금을 **더해 준다**(할인). 의도한 동작이다.
`coolFactor()` 를 전역으로 노출해 화면에서도 표시한다.

## 규칙

- 회선 한도를 넘기는 배치는 **버튼을 비활성**하고 이유를 보여준다. 조용히 실패하지 않는다.
- `cool > 1` 인 건물(원룸 1.15 등)은 할인이 아니라 **추가 비용**이다.
  절감액 표시에 `"+"` 를 무조건 붙이면 `+-2원` 으로 찍힌다 — 부호를 나눠 쓴다.
  (실제로 이 버그가 났고 스크린샷 검사에서 걸렸다)
- 로그에 건물 이름 뒤 조사를 붙일 때 `+e.name+" 은"` 처럼 쓰면 `원룸 은` 이 된다.
- 관리비(`fee`)는 F5 가 월 정산으로 걷는다. F3 는 걷지 않는다 — 이중 청구가 된다.
- 배치한 건물을 F2 에서 매도하면 `S.mine.at` 을 `null` 로 되돌려야 한다.
  F2 의 매도 함수를 고치는 대신, 훅에서 **보유 목록에 없으면 해제**하는 방어 코드를 둔다.
- 폰 대수는 `S.counts` (F0 소유)를 넘을 수 없다. 배치 합계를 검사한다.

## 끝내기 전

1. `ksk-verify` 절차 통과
2. 건물을 채굴장으로 지정 → 초당 전기요금이 실제로 달라지는 것이 화면에서 확인됨
3. 한도 초과 배치가 막히는지, 건물을 팔면 배치가 해제되는지 확인
4. 초당 비용이 음수가 되거나 현금이 폭증하지 않는지 (부호 오류 검사)
5. `PRD.md` §6 의 F3 항목 갱신
6. 커밋: `feat: F3 건물을 채굴장으로 — 수용 전력·냉각 효율 반영 …`
