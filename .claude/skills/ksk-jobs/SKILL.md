# F8 — 직업·커리어: 세 번째 소득원

**먼저 `ksk-contract` 스킬을 읽는다.** 작업 구역은 `grep -n "\[F8:" index.html` 세 곳뿐이다.

## 이 층이 하는 일

소득원이 셋이 된다 — **채굴/검증**(코인), **자산**(임대·차익), **노동**(월급).

월급의 역할은 단순한 돈벌이가 아니다. **채굴 초기의 방어선**이다. 통신비와 살림 전기요금이
현금을 갉아먹을 때, 월급이 있으면 코인을 헐값에 급매하지 않아도 된다. 그게 이 층의 존재 이유다.

**F2·F4 가 없어도 독립적으로 만들 수 있다.** 그래서 둘과 **동시에** 작업할 수 있다.

## 상태

```js
job: { id: null, months: 0, certs: [], edu: 0 },   // F8 — 현재 직업, 근속 개월, 자격, 학력 단계
```

## 직업 테이블

F8 JS 구역에 `JOBS` 상수를 만든다.

| 필드 | 뜻 |
|---|---|
| `id` | 영문 슬러그 |
| `name` | 표기 (예: `대기업 사원`) |
| `pay` | 월급 (원) |
| `hours` | 주간 근무시간 — 시간 점유(F8.4)에서 쓴다 |
| `needEdu` | 필요 학력 단계 (0 = 없음) |
| `needCert` | 필요 자격 id 또는 `null` |
| `odds` | 합격 확률 (0~1) |

최소 6개: `무직` / `알바` / `중소기업 사원` / `대기업 사원` / `공무원` / `부동산 중개사`.
월급은 살림 전기요금 + 통신비를 **덮되 넉넉하지는 않게** 잡는다. 월급만으로 부자가 되면
채굴을 할 이유가 사라진다.

## 자격·학력

`CERTS` 상수 — `부동산 중개사` 자격, 학위 과정 등. 각 항목에 **응시료·소요 개월·합격 확률**.
학력은 단계(0·1·2)로 두고 상위 직업의 `needEdu` 를 푼다.

## 만들 기능

| | 내용 |
|---|---|
| F8.1 | `JOBS` · `CERTS` 테이블 |
| F8.2 | 취직 — 지원 → 조건 검사 → 확률 판정, 실패 시 로그에 이유 |
| F8.3 | 월급 수령 — 아래 공유 접점 참고 |
| F8.4 | 근무 시간 점유 표시 (지금은 표시만, 제약은 v2) |
| F8.5 | 자격 시험·학위 — 응시료 지불, 기간 경과 후 판정 |
| F8.6 | 승진 — 근속 개월에 따라 월급 상승 |
| F8.7 | 중개사 개업 — 부동산 중개수수료를 **면제**하고, 개업 시 수입으로 전환 |

## 공유 접점

### 월급 (F5 가 없어도 동작하게)

```js
/* ==== [F8:직업] JS 시작 ==== */
tickHooks.push(function(dt){
  if(!S.job.id) return;
  const j = JOBS.find(x => x.id === S.job.id);
  S.cash += j.pay / 730 * dt;        // 1초 = 1게임시간, 한 달 = 730 게임시간
  S.job.months += dt / 730;
});
/* ==== [F8:직업] JS 끝 ==== */
```

`ksk-monthly`(F5)가 나중에 월말 일괄 정산으로 바꿀 수 있다. 그때는 F5 가 이 훅을 대체하되,
**F8 구역의 코드는 F5 가 지우지 않고 F8 담당이 정리한다.**

### 중개사 자격 (F2 와 맞물림)

`jobHasCert('realtor')` 를 **전역 함수로 노출**한다. F2 가 이 이름으로 수수료 면제를 판단한다.
F2 가 아직 없으면 아무도 안 부르지만, 이름은 미리 맞춰 둔다.

## 규칙

- 합격 확률은 **판정 결과를 로그에 남긴다.** 왜 떨어졌는지(조건 미달인지 확률인지) 보여야 한다.
- 회사명은 일반명사로 쓴다 (`대기업 사원`). 실제 기업명을 쓰지 않는다.
- 월급·응시료는 게임 균형용 근사치임을 화면에 남긴다.
- 직업은 하나만 가진다. 갈아타면 근속(`months`)이 0 으로 돌아간다.
