# F4 — 살림살이: 집 안을 채운다

**먼저 `ksk-contract` 스킬을 읽는다.** 작업 구역은 `grep -n "\[F4:" index.html` 세 곳뿐이다.

## 이 층이 하는 일

가전·가구·인테리어가 **장식이 아니라 계산에 들어간다.** 냉장고와 에어컨은 늘 전기를 먹고,
인테리어 등급은 임대료와 건물 가치를 올린다. 그래서 "집을 꾸미는 일"이 경제 행위가 된다.

**F2(부동산)가 아직 없어도 만들 수 있다.** 건물이 없으면 산 물건을 `보관함`에 넣어 두고,
F2 가 끝난 뒤 `ksk-mining-infra`(F3) 나 후속 작업에서 건물에 배치하도록 연결한다.
이 독립성 덕분에 F2·F8 과 **동시에** 작업할 수 있다.

## 상태

```js
hh: { items: {}, placedAt: null },   // F4 — items: {품목id: 개수}, placedAt: 건물id 또는 null(보관함)
```

## 품목 카탈로그

F4 JS 구역에 `GOODS` 상수를 만든다.

| 필드 | 뜻 |
|---|---|
| `id` | 영문 슬러그 |
| `name` | 표기 이름 (예: `양문형 냉장고`) |
| `cat` | 분류 — `가전` / `가구` / `인테리어` |
| `cost` | 구매가 (원) |
| `w` | 상시 소비전력 (W). 가구·인테리어는 0 |
| `grade` | 인테리어 등급 점수 (0~10) |
| `life` | 수명 (게임 개월) — F4.5 감가상각에서 쓴다 |

분류별로 4~5개씩, 총 12~15개. 저가 생활필수품부터 고급 인테리어까지 폭을 둔다.

- **가전**은 `w` 가 크고 `grade` 가 낮다 (냉장고 150W, 에어컨 1,800W, 세탁기 500W…)
- **가구·인테리어**는 `w`=0 이고 `grade` 가 높다
- 이 대비가 이 층의 긴장이다: 편의를 사면 전기요금이 늘고, 등급을 사면 자산 가치가 는다

## 만들 기능

| | 내용 |
|---|---|
| F4.1 | `GOODS` 카탈로그 |
| F4.2 | 구매·설치 패널 — 분류 탭 또는 그룹, 보유 개수 표시 |
| F4.3 | 소비전력 반영 — 총 W 를 초당 전기요금에 더한다 (아래 공유 접점 참고) |
| F4.4 | 인테리어 등급 합계 → 임대료·건물가치 배수 (F5·F2 가 읽어 갈 값을 노출) |
| F4.5 | 감가상각 — 수명이 지나면 등급이 떨어지고 교체가 필요해진다 |

## 공유 접점 — 전기요금

`costPerSec()` 은 F0 소유라 직접 고치지 않는다. 대신 F4 구역에서 훅으로 더한다.

```js
/* ==== [F4:살림살이] JS 시작 ==== */
function hhWatts(){ /* 보유 품목의 w 합계 */ }
tickHooks.push(function(dt){
  if(S.cash > 0) S.cash -= elecRate() * (hhWatts()/1000) * dt;   // 1초 = 1게임시간
});
/* ==== [F4:살림살이] JS 끝 ==== */
```

`hhWatts()` 와 `hhGrade()`(등급 합계)를 **전역 함수로 노출**한다. F5·F2 가 이 이름으로 읽어 간다.
이름을 바꾸면 다른 스킬이 깨지므로 바꾸지 않는다.

## 규칙

- 살림 전기요금은 **채굴을 끄든 켜든** 나간다. 냉장고는 늘 돌아간다. 그게 이 층의 요점이다.
- 현금이 0 이하로 내려가면 더 깎지 않는다 (파산 판정은 F0 소유).
- 상품명은 일반명사로 쓴다 (`양문형 냉장고`). 실제 브랜드·모델명을 쓰지 않는다.
- 가격은 게임 균형용 근사치임을 화면에 남긴다.

## 끝내기 전

1. `ksk-verify` 절차 통과
2. 구매 → 보유 개수 증가 → 전기요금이 실제로 늘어나는 것이 화면에서 확인됨
3. 채굴을 끈 상태에서도 살림 전기요금이 나가는지 확인
4. `PRD.md` §6 의 F4 항목 갱신
5. 커밋: `feat: F4 살림살이 카탈로그·구매·소비전력 반영 — …`
