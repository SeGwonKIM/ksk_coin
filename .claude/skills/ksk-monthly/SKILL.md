# F5 — 월 정산: 현금흐름을 한 달 단위로 묶는다

**먼저 `ksk-contract` 스킬을 읽는다.** 작업 구역은 `grep -n "\[F5:" index.html` 세 곳뿐이다.

## 선행 조건

정산할 항목이 있어야 의미가 있다. 최소 하나는 있어야 한다.

```bash
grep -n "ESTATES" index.html      # F2 — 임대료·관리비·보유세
grep -n "hhWatts" index.html      # F4 — 살림 전기요금
grep -n "JOBS" index.html         # F8 — 월급
```

셋 다 없으면 작업을 멈추고 선행 스킬이 필요하다고 보고한다.
있는 것만으로 시작해도 된다 — 없는 항목은 정산 명세에서 빠지면 된다.

## 이 층이 하는 일

지금은 모든 비용이 **초당 조금씩** 빠져나가서 실감이 없다. 월말에 한꺼번에 정산하면
"이번 달 흑자인가 적자인가"라는 판단이 생긴다. 그게 경제 게임의 리듬이다.

## 상태

```js
fin: { month: 0, last: null },   // F5 — 누적 개월, last: 지난달 정산 명세 객체
```

## 게임 시계

시간 축척은 `1 실제초 = 1 게임시간`이고 한 달은 **730 게임시간**이다.

```js
/* ==== [F5:월정산] JS 시작 ==== */
tickHooks.push(function(dt){
  S.fin.month += dt / 730;
  while(Math.floor(S.fin.month) > (S.fin.done || 0)){
    S.fin.done = (S.fin.done || 0) + 1;
    settle();                       // 월말 정산
  }
});
/* ==== [F5:월정산] JS 끝 ==== */
```

**`while` 로 감는다.** `dt` 상한이 2초라 한 틱에 한 달을 넘길 수는 없지만, 방어로 둔다.
연·월 표시는 `1년차 3월` 처럼 `S.fin.month` 에서 계산한다.

## 정산 명세

`settle()` 이 항목별 금액을 모아 `S.fin.last` 에 넣고, 합계를 현금에 반영한 뒤 로그에 한 줄 남긴다.

| 수입 | 근거 |
|---|---|
| 임대수익 | 보유 건물의 `rent` 합계 × 인테리어 등급 배수(`hhGrade()`, 있으면) |
| 월급 | 현재 직업의 `pay` (F8 이 이미 초당 지급하고 있으면 **중복 청구하지 않는다**) |
| 중개 수입 | F8.7 개업 상태일 때 |

| 지출 | 근거 |
|---|---|
| 관리비 | 보유 건물의 `fee` 합계 |
| 보유세 | 보유 건물 평가액의 0.15% (게임 균형용 근사) |
| 살림 전기 | F4 가 이미 초당 청구하면 **중복 청구하지 않는다** |

**중복 청구가 이 층의 가장 큰 위험이다.** 각 항목을 넣기 전에 그 항목이 이미 초당으로
빠져나가고 있는지 `grep` 으로 확인한다. 이미 있으면 (a) 그 훅을 없애고 월 정산으로 옮기거나,
(b) 월 정산에서 뺀다. **어느 쪽을 골랐는지 코드 주석에 남긴다.**

## 만들 기능

| | 내용 |
|---|---|
| F5.2 | 게임 연·월 표시, 월말 정산과 명세 패널 |
| F5.3 | 임대수익 |
| F5.4 | 파산 회생 — 현금이 마이너스면 건물 강제 매각으로 메우고, 팔 것이 없으면 파산 |
| F6.2 | 연·월·일 표시 (F5 와 같은 시계를 쓰므로 여기서 함께 만든다) |

## 규칙

- 정산은 **명세를 보여준다.** 합계만 바꾸고 끝내면 왜 적자인지 알 수 없다.
- 파산 판정 자체는 F0 소유다(`tickMarket` 안). F5 는 그 앞단에서 회생(강제 매각)만 시도한다.
- 세율·요율은 게임 균형용 근사치임을 화면에 남긴다.
